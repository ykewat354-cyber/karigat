# What the SWE-bench submissions disclose about agent coordination

**Karigat should start with one patch writer and a verifier.** The two highest-scoring families in the PRD's [Verified snapshot](https://api.github.com/repos/SWE-bench/swe-bench.github.io/git/blobs/1609701d2d73b0f785d28d247155886062d942f1) describe agents acting on tool feedback. Other entrants document useful places to delegate: finding code, discovering test commands, or comparing independently generated patches. Rank alone cannot establish which design works best at the same cost.

**Coverage (23 Nov 2026):** all 20 named submissions, in PRD order. Family links lead to the submitted README, except mini-SWE-agent, which has metadata instead. These are authors' descriptions, not independent reproductions. **Loop** means autonomous task execution is described, with no inter-agent handoff established by the cited evidence. **Handoff** means distinct agent roles or invocations explicitly exchange a task or result; the qualifier distinguishes specialists from repeated runs of one agent. **Limited** means the run's control flow is substantially undisclosed. The last column gives recommendations, not claims about the submissions.

**First comparison to run:** hold model, tasks, acceptance checks and spend cap constant. Compare the serial baseline with one read-only search worker; track verified resolutions, elapsed time and total cost, including failed attempts. Test candidate generation and selection separately: it changes the number of patches evaluated as well as the division of work.
